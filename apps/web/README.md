# PotatoFlow Web

PotatoFlow 是一套本地优先、可选云同步的个人执行系统：把 Codex 整理出的项目计划导入网页，在“今天—日历—项目—问题”四个视图中执行、记录、复盘。网页不调用 AI API，不预置任何个人项目。

第一次使用请先阅读[零基础下载与使用教程](../../docs/BEGINNER_GUIDE.zh-CN.md)。

## 快速开始

需要 Node.js 22.13 或更高版本。

```bash
npm install
npm run dev
```

打开终端显示的本地地址。默认开发地址通常为 `http://localhost:3000`；本项目也提供：

```bash
npm run dev:lan
```

它会监听 `0.0.0.0:3001`，便于同一局域网内测试。不要把本地开发服务直接暴露到公网。

## 验证

```bash
npm test
npm run lint
```

## 功能

- 空白初始化与三步首次使用引导
- 导入 Skill 生成的项目 JSON，支持新建或按稳定 ID 合并更新
- 导入预览可选择无源文件、全部任务共用文件或每个任务分别关联文件
- 导入前展示新增、修改、不变、保留和删除清单；完全相同的内容不会重复写入
- 使用项目修订号识别旧版本更新；冲突、未知删除和重复字段会阻止导入
- 任务调整保留最近 10 个定义版本；导入前自动保存最多 3 个浏览器内恢复快照
- 自定义一次性、每天、工作日、周末及日期范围任务
- 今日任务分组、优先级、暂停、步骤报告、验收清单与自动进度
- 每个任务拥有独立备注，可从 JSON 导入，也可在任务详情、项目编辑或自定义任务中随时维护
- 日期选择、月历总览与当日任务列表
- 项目总览、编辑、撤销、新增/删除任务、原文件索引
- 任务详情直接显示并打开与当前任务相关的 Word、PDF、Markdown 或文本资料
- 项目总览上传文件前可选择“全部任务共用”或指定任务；旧文件可以随时补关联
- 项目总览可查看并一键统一全部任务标签，单条任务仍可独立覆盖
- 问题记录、阻碍标记、Codex 分析结果与解决状态
- 当前任务、当前项目、全量备份三种导出范围
- 全量备份恢复（替换当前浏览器数据）
- 桌面与移动端响应式布局
- 在 Sites 部署中登录同一个 ChatGPT 账号，可通过 D1 同步项目、任务、进度、备注和问题记录
- 首次同步与版本冲突均由用户明确选择本机或云端数据，不会自动覆盖
- 云端每次更新前保留最近 10 个历史版本，本机仍保留恢复快照与离线缓存

## 数据与隐私

- 未登录时，项目、任务和问题只保存在当前浏览器的 `localStorage`。
- 登录后，结构化任务数据以 D1 云端快照为同步来源，本地浏览器继续保留离线缓存。
- 同步接口只使用服务端提供的稳定用户标识隔离数据，不接收客户端自行提交的用户 ID，也不把该标识传给网页界面。
- 上传的 Word、PDF、Markdown 和文本文件保存在当前浏览器的 IndexedDB。
- JSON 全量备份不包含上传文件本体；恢复后需重新添加原文件。
- Word、PDF 等源文件暂不跨设备同步；手机与电脑只同步结构化任务数据。
- 清理站点数据、隐私模式退出或浏览器故障可能导致本地数据丢失，请定期导出全量备份。

## 与 Codex 配合

1. 安装 `skills/potatoflow`。
2. 在 Codex 中使用 `$potatoflow` 建档，并确认是否有源文件、共用/分别关联方式，以及每条任务是否需要备注。
3. 在网页选择“导入项目 JSON”；检查变更后按提示选择实际本地文件。
4. 遇到问题时只导出“当前任务”，交给 Codex 分析。
5. 调整已有规划时导出“当前项目”，让 Skill 保留 ID 和项目修订号后生成合并更新 JSON。
6. 粘贴后先点“检查变更”；核对五类统计和冲突提示，再确认导入。

同一个更新 JSON 可以重复检查，但内容完全相同时不会再次写入。未出现在 `tasks`
中的旧任务默认保留；只有 `deleted_task_ids` 明确列出且项目中真实存在的任务才会删除。

完整说明见交付包中的《PotatoFlow 用户使用手册》。

## 开源部署边界

公开源码默认仍可保持纯本地模式。部署者只有将 `.openai/hosting.json` 的 `d1` 设置为 `DB` 并使用 Sites 的 ChatGPT 登录身份后，才会启用跨设备同步；不要把未配置 D1 的本地部署误当成云端账户系统。
## 任务结构

- 阶段标题仅用于分组并显示子任务完成数量。
- 子任务标题前的勾选框可一键完成全部步骤；每条执行步骤也可单独勾选并添加备注。
- 执行步骤可以逐项勾选并添加独立备注；完成标准用于验收查看。
- 每个任务只保留一个统一结果汇报框和一个问题框。
- 旧版步骤勾选与步骤报告继续保存在兼容字段中，首次读取时会汇总到任务级报告。
