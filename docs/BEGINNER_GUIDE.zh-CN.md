# PotatoFlow 零基础下载与使用教程

这份教程写给第一次接触 GitHub、Codex Skill、Node.js 和 JSON 的用户。你不需要会编程，也不需要自己编写 JSON。

## 1. 先理解 PotatoFlow 的三个部分

PotatoFlow 不是一个已经托管好的在线账号系统，它由三个部分组成：

1. **PotatoFlow Skill**：安装到 Codex，负责提问、梳理项目、生成和更新任务 JSON。
2. **PotatoFlow 网页**：在浏览器里显示今天任务、日历、项目、问题和执行进度。
3. **项目 JSON**：Skill 与网页之间交换项目内容的文本。通常只需要复制和粘贴，不需要看懂或手写。

最简单的工作方式是：

```text
在 Codex 里说清目标
→ PotatoFlow Skill 生成项目 JSON
→ 把 JSON 导入网页
→ 在网页执行、勾选、记录结果
→ 需要调整时导出当前项目，再交给 Codex
```

## 2. 你应该下载哪一个文件

进入 [PotatoFlow v0.6.1 发布页面](https://github.com/chenhaha299-hub/PotatoFlow/releases/tag/v0.6.1)，可以看到两个下载包：

- `potatoflow-skill-v0.6.1.zip`：只包含 Skill。只想让 Codex 帮你规划项目时下载这个。
- `PotatoFlow-source-v0.6.1.zip`：完整源码，包含 Skill、网页、教程和测试。需要使用任务网页时下载这个。

如果你希望完整使用 PotatoFlow，建议两个都安装：

1. 先安装 Skill。
2. 再下载完整源码并启动网页。

## 3. 安装 PotatoFlow Skill

### 方法 A：让 Codex 从 GitHub 安装

这是推荐方式。

在 Codex 新建一个任务，发送：

```text
请使用 skill-installer 从 GitHub 安装 PotatoFlow Skill：
仓库：chenhaha299-hub/PotatoFlow
路径：skills/potatoflow
安装完成后告诉我安装目录。
```

安装完成后：

1. 关闭当前任务。
2. 重新打开 Codex，或新建一个任务。
3. 发送下面的验证指令：

```text
使用 $potatoflow 简单介绍你能帮我做什么，现在不要创建项目。
```

如果 Codex 能识别 `$potatoflow` 并介绍项目建档、任务更新、问题分析和备份恢复，说明安装成功。

### 方法 B：手动安装 Skill

当自动安装不可用时使用这种方法。

#### Windows

1. 下载 `potatoflow-skill-v0.6.1.zip`。
2. 解压后找到 `potatoflow` 文件夹。
3. 按 `Win + R`。
4. 输入 `%USERPROFILE%\.codex\skills`，按回车。
5. 把整个 `potatoflow` 文件夹复制进去。
6. 重新打开 Codex，或新建任务。

最终目录必须是：

```text
%USERPROFILE%\.codex\skills\potatoflow\SKILL.md
```

不要变成下面这种多套一层的结构：

```text
%USERPROFILE%\.codex\skills\potatoflow\potatoflow\SKILL.md
```

#### macOS 或 Linux

把 `potatoflow` 文件夹放到：

```text
~/.codex/skills/potatoflow
```

确认下面的文件存在：

```text
~/.codex/skills/potatoflow/SKILL.md
```

### Skill 无法识别怎么办

依次检查：

1. `SKILL.md` 是否直接位于 `potatoflow` 文件夹内。
2. 是否完整复制了 `references`、`scripts` 和 `agents` 文件夹。
3. 是否在安装后重新打开 Codex或新建任务。
4. 指令里是否明确写了 `$potatoflow`。
5. 是否误把压缩包本身放进 Skills 目录，而没有解压。

## 4. 下载并启动 PotatoFlow 网页

### 4.1 准备环境

网页需要：

- Windows、macOS 或 Linux 电脑。
- Chrome、Edge、Safari 等现代浏览器。
- Node.js 22.13 或更高版本。

Node.js 请从 [Node.js 官方网站](https://nodejs.org/)下载安装。安装完成后，打开终端输入：

```text
node -v
npm -v
```

如果两条命令都显示版本号，说明环境可用。

### 4.2 解压完整源码

1. 下载 `PotatoFlow-source-v0.6.1.zip`。
2. 解压到一个容易找到的目录，例如：

```text
D:\Apps\PotatoFlow
```

尽量避免放在层级很深、名称很长的文件夹中。

### 4.3 第一次启动

打开终端，进入网页目录。

Windows 示例：

```powershell
cd "D:\Apps\PotatoFlow\apps\web"
npm install
npm run dev
```

macOS 或 Linux 示例：

```bash
cd ~/Apps/PotatoFlow/apps/web
npm install
npm run dev
```

第一次运行 `npm install` 会下载网页依赖，需要等待一段时间。成功后，终端会显示一个本地网址，通常类似：

```text
http://localhost:3000
```

按住 `Ctrl` 点击网址，或复制到浏览器打开。

看到空白的 PotatoFlow 首页和首次使用引导，就说明启动成功。

### 4.4 第二次以后怎么启动

以后不需要重复执行 `npm install`。进入同一个目录后运行：

```text
npm run dev
```

终端窗口必须保持打开。关闭终端或按 `Ctrl + C` 后，网页服务会停止。

### 4.5 PowerShell 提示“禁止运行脚本”

可以把 `npm` 改成 `npm.cmd`：

```powershell
npm.cmd install
npm.cmd run dev
```

### 4.6 在同一 Wi-Fi 下用手机打开

在电脑的网页目录运行：

```text
npm run dev:lan
```

然后：

1. 确保电脑和手机连接同一个 Wi-Fi。
2. 在电脑终端运行 `ipconfig`（Windows）或 `ifconfig`（macOS/Linux）。
3. 找到电脑当前局域网 IPv4 地址。
4. 在手机浏览器打开 `http://电脑局域网地址:3001`。
5. Windows 防火墙询问时，只允许“专用网络”。

注意：

- 电脑必须开机，终端服务必须保持运行。
- `localhost` 只能在启动服务的那台电脑上打开，手机不能用电脑的 `localhost`。
- 手机浏览器与电脑浏览器的数据彼此独立，不会自动同步。
- 不要把本地开发端口直接暴露到公网。

## 5. 创建第一个项目

### 5.1 从网页复制建档提示词

1. 打开 PotatoFlow 网页。
2. 点击右上角“导入项目”。
3. 选择“导入项目 JSON”。
4. 找到“复制建档提示词”。
5. 点击复制。

### 5.2 在 Codex 建档

把提示词粘贴到安装了 PotatoFlow Skill 的 Codex 任务中。

Skill 会分几轮询问：

- 想完成什么项目。
- 怎样才算成功。
- 已经有哪些资源。
- 有哪些时间、预算或隐私限制。
- 每周或每天能投入多少时间。
- 是否存在每天、工作日、周末或指定日期范围的周期任务。
- 是否需要 Word、PDF、Markdown 或文本源文件。
- 源文件是全部任务共用，还是每个任务分别关联。
- 每个任务是否需要单独备注。

不知道的内容可以直接回答“不确定”或“请先给建议”，Skill 会把它标记为待确认假设，不会冒充你的事实。

### 5.3 确认项目摘要

Skill 不会立刻生成最终 JSON，而是先给你一份项目摘要。重点检查：

- 项目目标是否准确。
- 成功标准是否能被验证。
- 日期和工作量是否现实。
- 有没有把长期目标拆得过细。
- 源文件关联方式是否正确。
- 备注是否来自你本人，而不是自动编造。

确认无误后回复：

```text
确认生成
```

### 5.4 导入 JSON

1. 复制 Codex 输出的完整 JSON。
2. 返回 PotatoFlow 的“导入项目 JSON”。
3. 选择“新建项目”。
4. 粘贴 JSON。
5. 点击“检查变更”。
6. 核对项目名称、任务数量、日期、源文件要求和变更摘要。
7. 如果需要源文件，根据提示选择本机文件。
8. 确认导入。

成功标志：

- 首页出现当天任务。
- “项目”页面出现新项目。
- “日历”页面能看到任务日期。
- 打开任务能看到为什么做、执行步骤和完成标准。

## 6. 每天怎么使用

### 6.1 查看当天任务

进入“今天”页面：

1. 点击日期可以自由选择某一天。
2. 左右箭头切换前一天和后一天。
3. 任务会按照日常、工作、娱乐、其他分组。
4. 同一分组中优先级高的任务更靠前。
5. 点击项目标题旁的小三角可以折叠或展开。

### 6.2 执行任务

打开一条任务后：

1. 先阅读“为什么做”。
2. 按顺序完成“执行步骤”。
3. 每完成一步，在该步骤下填写完成情况或结果数据。
4. 勾选已经完成的步骤。
5. 核对“完成标准”并勾选。
6. 在页面底部统一保存并退出。

进度由执行步骤和验收清单自动计算，不需要手动填写完成百分比。

当全部必要项目完成后：

- 进度变为 100%。
- 任务状态自动变为已完成。
- 页面显示满分王冠效果。

### 6.3 暂停任务

“暂停”和“未完成”不是一回事。

- 暂时不执行，但以后还会继续：使用“暂停任务”。
- 还没完成但仍在正常推进：保持未完成即可。
- 恢复执行时，再点击“恢复任务”。

## 7. 执行中遇到问题怎么和 Codex 配合

网页本身不会调用 AI，也不会自动把数据上传给 Codex。

正确流程：

1. 打开发生问题的任务。
2. 在“执行中遇到问题”中写清发生了什么、已经尝试过什么。
3. 如果问题确实阻碍继续执行，勾选“这个问题阻碍任务继续”。
4. 保存并退出。
5. 打开“问题”页面，选择这条问题。
6. 点击“导出数据”，选择“当前任务”，复制完整内容。
7. 粘贴到 Codex，并发送：

```text
使用 $potatoflow 分析下面这个任务问题。请结合项目目标、原任务要求和我已经尝试的方式，
给出最可能原因、最小验证步骤、具体解决方法，以及成功和失败分别会看到什么。
```

8. 把任务数据粘贴在提示词后面。
9. 将 Codex 的结论复制回问题详情中的“分析结果”。
10. 实际验证成功后，再把问题标记为已解决。

不要把“今天没有问题”或普通完成汇报创建成问题。完成情况应写在对应执行步骤下。

## 8. 修改现有项目而不产生重复任务

不要让 Codex凭记忆重新生成整个项目。安全流程是：

1. 在网页点击“导出数据”。
2. 选择“当前项目”。
3. 复制导出内容。
4. 粘贴给 Codex，并说明想修改什么。

示例：

```text
使用 $potatoflow 更新这个现有项目。
保留项目 ID、revision、任务 ID、完成记录和问题记录。
把下周工作日每天的可用时间调整为 60 分钟，并把超过负荷的任务顺延。
先列出新增、修改、改期、保持不变和准备删除的内容，等我确认后再生成 JSON。
```

Codex 生成更新 JSON 后：

1. 回到“导入项目 JSON”。
2. 选择“合并更新已有项目”。
3. 点击“检查变更”。
4. 仔细核对新增、修改、保留、删除和冲突。
5. 没有冲突后再确认导入。

重要规则：

- 相同 ID 和相同内容不会重复创建。
- 更新 JSON 中没有出现的旧任务默认保留。
- 只有 `deleted_task_ids` 明确列出的任务才会删除。
- 如果网页提示修订号冲突，重新导出最新的“当前项目”，再让 Codex 生成更新。
- 不要为了完成导入而绕过冲突提示。

## 9. 不经过 Codex，手动创建任务

临时任务可以直接在网页创建。

点击“导入项目”后选择“自定义任务”，可以设置：

- 归属项目。
- 任务标题和要达到的结果。
- 为什么做。
- 执行步骤。
- 完成标准。
- 任务备注。
- 预计时长。
- 日常、工作、娱乐、其他标签。
- 优先级。
- 一次性、每天、工作日、周末或日期范围。

适合手动创建的内容：

- 临时会议准备。
- 每天运动。
- 每个工作日整理消息。
- 周末复盘。
- 某一段时间内持续进行的练习。

复杂项目仍建议使用 Skill 建档，因为 Skill 会同时检查目标、依赖、工作量和验收标准。

## 10. 使用 Word、PDF 等源文件

建档时有三种模式：

1. 不需要源文件。
2. 所有任务共用同一份或多份源文件。
3. 每个任务关联不同的源文件。

JSON 只记录文件用途和任务关系，不包含文件本体，也不写入电脑绝对路径。

实际文件需要在网页导入时由你亲自选择。文件会保存在当前浏览器的 IndexedDB 中。

注意：

- 换浏览器后需要重新上传源文件。
- 恢复 JSON 备份后需要重新上传源文件。
- 删除浏览器站点数据会删除这些文件。
- 不要把客户机密资料提交到公开 GitHub 仓库。

## 11. 备份、恢复和换浏览器

“导出数据”有三个范围：

- **当前任务**：给 Codex 分析一条任务及其问题。
- **当前项目**：让 Codex 安全更新现有项目。
- **全量备份**：恢复整个浏览器中的项目、任务、进度和问题。

### 建议备份习惯

- 每周至少导出一次全量备份。
- 大规模调整项目之前先备份。
- 恢复其他备份之前先导出当前备份。
- 备份文件保存在自己的私人文件夹，不要上传到公开仓库。

### 恢复完整备份

恢复会替换当前浏览器中的全部 PotatoFlow 数据：

1. 打开恢复完整备份。
2. 粘贴或选择全量备份。
3. 仔细确认备份来源。
4. 按页面要求输入“恢复”。
5. 确认替换。
6. 恢复完成后重新添加 Word、PDF 等源文件。

不要把两个完整备份直接互相合并。需要合并时，以“当前项目”为单位交给 Skill 分析和预览。

## 12. 数据保存在哪里

默认情况下：

- 项目、任务、问题和完成进度保存在当前浏览器的 `localStorage`。
- Word、PDF、Markdown 和文本文件保存在当前浏览器的 IndexedDB。
- 网页不调用 AI API。
- 不同浏览器不会自动同步。
- 不同电脑和手机不会自动同步。
- 隐私模式关闭后，数据可能被清除。
- 清理浏览器站点数据会删除本地 PotatoFlow 数据。

如果电脑关机，本地网页不能从手机访问。当前开源版本不是云端同步服务。

## 13. 常见问题

### 网页打不开

检查运行网页的终端是否还开着。终端关闭后重新执行：

```text
npm run dev
```

### `localhost` 在手机打不开

`localhost` 代表手机自己，不代表电脑。请在电脑运行 `npm run dev:lan`，然后使用电脑局域网地址和端口 `3001`。

### 换浏览器后项目不见了

这是当前版本的正常行为。数据保存在原浏览器。请从原浏览器导出全量备份，再到新浏览器恢复。

### 所有步骤已完成，任务仍未完成

同时检查：

- 执行步骤是否全部勾选。
- 完成标准是否全部勾选。
- 是否存在尚未保存的修改。
- 保存并退出后是否刷新了首页状态。

### 重新导入会不会重复

- 新项目请选择“新建项目”。
- 更新现有项目请选择“合并更新已有项目”。
- 更新时必须保留原项目 ID、revision 和任务 ID。
- 导入前先查看变更预览。

### 导入提示修订冲突

说明 Codex 使用的项目导出不是最新版本。重新导出“当前项目”，再生成更新 JSON。

### 恢复后看不到源文件

全量 JSON 备份不包含文件本体。需要在项目总览重新添加并关联本地文件。

### `npm install` 失败

依次检查：

1. `node -v` 是否达到 22.13。
2. 当前终端是否位于 `apps/web`。
3. 网络是否能访问 npm。
4. 是否有足够磁盘空间。
5. PowerShell 报脚本限制时改用 `npm.cmd`。

## 14. 更新和卸载

### 更新 Skill

1. 先备份自己的项目数据。
2. 下载新版 Skill。
3. 关闭 Codex。
4. 用新版 `potatoflow` 文件夹替换旧文件夹。
5. 重新打开 Codex，并验证 `$potatoflow`。

不要把个人导出数据、项目文档或 `.potatoflow` 运行目录混进 Skill 文件夹。

### 卸载 Skill

关闭 Codex，删除个人 Skills 目录中的 `potatoflow` 文件夹即可。卸载 Skill 不会自动删除浏览器中的 PotatoFlow 数据。

### 更新网页

1. 先在旧网页导出全量备份。
2. 下载并解压新版源码到新文件夹。
3. 在新版 `apps/web` 中执行 `npm install` 和 `npm run dev`。
4. 打开新版网页后恢复全量备份。
5. 重新添加源文件。

- [ ] 已在 Codex 完成项目建档摘要。
- [ ] 回复“确认生成”后拿到了 JSON。

- [ ] 知道如何填写步骤完成情况。
- [ ] 知道问题与普通完成汇报的区别。
- [ ] 知道更新项目时要先导出“当前项目”。

完成以上内容后，就可以开始正常使用 PotatoFlow。
